# Philosophy bank

Philosophy is the conceptual fourth frame: reusable foundations invoked where needed by nodes in Status Quo, Transformative Action and Goal State. This increment adds no fourth canvas column or separate mapping mode.

## Node workflow

Select an ordinary node, then **Philosophy**. Owners can choose existing bank entries or expand **Create a new idea**, choose **Definition**, **Standard**, **Principle**, **Belief** or **Other**, and enter a title and idea. **Save philosophy** saves a new bank entry and its use on the selected node together. Multiple ideas may be attached. Filtering the bank does not discard checked selections.

Definitions explain terms; standards state criteria; principles state guiding commitments; beliefs describe views about nature or the world; Other accommodates foundations that do not fit those categories. Users choose the type; nothing is automatically classified.

The Philosophy bank is available in Map Library. An idea can be reused across nodes and maps. Unchecking it removes that node's use while retaining the bank entry. Attachments apply to the selected node, not automatically to descendants or linked topics. Existing edge references remain supported.

## Meaning, privacy and history

Existing definitions and standards retain their identities, saved versions and attachments. New types use the same author-owned records and permissions. Unused bank entries remain private. Readers see only the exact versions invoked on accessible sources, with type and author attribution; they cannot edit the source owner's bank.

Editing a bank entry adds a version. Existing uses stay on their chosen version until reviewed and updated individually. Archived entries are excluded from new choices but existing uses remain readable. Earlier context text and references remain available in history. Removing an attachment does not erase earlier versions.

Create exposes Philosophy directly on the node menu and in inspection. Shared Inquiry, Compare and Argument menus offer one Philosophy action. Source browsing offers a read-only Philosophy window. The standalone export supports the same idea types. Facilitators retain existing reference permissions; creating or editing bank entries remains unavailable while acting for another participant.

## Compatibility and checks

`philosophy-v1` protects older account clients when their visible workspace or submitted changes contain the new idea types, including historical and copied references. Those tabs are asked to reopen the updated app while keeping drafts. Existing files with only definitions and standards continue to load. Rollback after new types are saved must preserve their validation and display support.

The additive migration broadens only the existing bank-entry and premise-reference validators. Table access, ownership rules, invoker security and version history remain unchanged. Coverage includes all five types, atomic create-and-attach, privacy, reuse, pinned versions, removal, invalid writes, compatibility, read-only sources, shared menus and narrow-screen use. See deployment status for publication evidence.
